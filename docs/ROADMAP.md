# Canvas 文件预览扩展：产品方向

用户愿景：逐步支持其他学校的 Canvas、允许选择 PDF 阅读器、支持更多文件类型，并让不熟悉计算机且不使用 VPN 的用户也能安装使用。

## 当前版本

独立 WebExtension；复旦 eLearning 是首个适配平台；PDF 是首个文件类型。学校、文件类型和阅读器在 `extension/catalog.js` 分开登记。内容脚本和后台只依赖统一文件描述，平台适配负责识别 Canvas 文件地址。构建时由学校配置生成注入范围和默认权限。

当前统一使用内置 PDF.js 阅读器，文件解析和页面显示使用打包资源，无需外部 CDN。原有用户脚本保留为兼容入口。用户已明确优先实现第 4 项愿景（免油猴、容易安装），阅读器切换等其余功能按后续迭代推进。

## 推进顺序与验收

1. **安装和分发。** 优先准备 Edge Add-ons，其次 Firefox 签名及 Chrome Web Store。在中国大陆常见网络环境实测商店访问和安装；不能仅凭“无需 VPN”的目标宣称所有网络都可用。对校园分发准备有版本号、校验值的官方镜像；镜像需要学校/所有者提供发布位置。Chrome 普通版不支持任意网页一键安装未上架扩展，下载 ZIP 不能替代商店上架。
2. **第二所 Canvas 学校。** 选择一个真实部署，确认域名、Canvas 文件接口、登录/SSO、文件重定向和权限后登记适配。用该校有访问权的测试文件验证再宣称支持。保持学校权限最小化；以后添加学校时解释新增权限。后续可增加用户主动授权的自定义 Canvas 站点，不能通过向所有网站默认注入脚本实现。
3. **阅读器选择。** 后续加入内置阅读器与浏览器原生阅读器切换；再评估其他本地阅读器。不下载远程可执行插件，不默认把私有课程文件发送给在线阅读服务。对密码文件、批注、可访问性等功能按具体阅读器验证。
4. **更多格式。** 优先支持图片与纯文本，再评估 Markdown、音视频；Office 文档另立功能范围，权衡浏览器本地解析、版式保真、体积和隐私。非 PDF 文件不交给 PDF 阅读器，格式处理器要做 MIME/签名校验和大小限制。

## 架构边界

- 平台：域名许可、Canvas 链接识别、文件定位与登录要求。
- 文件：规范化后的来源 URL、文件名、格式及读取结果。
- 阅读器：只负责所支持格式的展示和用户偏好。
- 分发：浏览器清单、商店签名、离线资源、升级路径与安装帮助。

先把同学能安装、能打开文件、失败时知道怎么办验证好，再逐步扩大范围。多学校、多格式均为路线图，不是当前版本已完成的兼容性声明。
